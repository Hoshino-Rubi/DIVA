# Any2Xsampa

Any2Xsampa converts singing audio into a stable phones/IPA representation and
then exports X-SAMPA or engine-specific phonemes. Phones, IPA, and articulatory
evidence are the internal truth layer; X-SAMPA and Vocaloid phonemes are export
formats only.

This is the clean development tree. Recovery evidence, damaged source files,
agent outputs, and recovery-only tooling are intentionally not included.

## Included runtime

- `.venv`: Python 3.14 environment with Torch 2.13.0+cu126, ONNX Runtime GPU 1.26.0,
  Qwen ASR, gRPC, and the training dependencies used by the project.
- `models/onnx-espeak`: verified ONNX/eSpeak recognizer and tokenizer assets.
- `models/qwen3-asr-0.6b`: verified Qwen3-ASR model assets.
- `.nuget`: local packages used by the WinUI build.
- `Human-made_Sections`: validated Miku V4C VSQX templates.
- `examples/accepted`: a user-accepted Vocaloid4 VSQX generated by the real
  ONNX/eSpeak path.

Model hashes and upstream revisions are recorded in `models/MANIFEST.json`.

## Quick checks

Run commands from this directory:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider
.\.venv\Scripts\any2xsampa.exe --help
.\.venv\Scripts\any2xsampa-api.exe --help
.\.venv\Scripts\any2xsampa-grpc.exe --help
```

Activate the environment when an interactive shell is preferred:

```powershell
.\.venv\Scripts\Activate.ps1
```

The fixture recognizer remains the default runnable mode. The explicit
`onnx-espeak` real backend uses the verified bundled model/tokenizer when no
model path is supplied. Explicit CUDA requests fail when CUDA cannot be
activated; only `device=auto` may record a CPU fallback. No real-mode failure
silently selects a stub.

The Python audio-to-VSQX product tool accepts external pitch/phone evidence or
explicitly runs the local adapters:

```powershell
.\.venv\Scripts\python.exe tools\build_miku_v4c_audio_draft_vsqx.py `
  --audio input.wav --lyrics "喜歡你" `
  --template "Human-made_Sections\今天我.vsqx" `
  --output-root .state\runs\miku-product `
  --auto-pitch --auto-phones --recognizer-device cuda
```

This path creates one VSQX note per pitch candidate and requires real lyric and
phone evidence. When one held pitch candidate directly crosses explicit
phone/lyric boundaries, the fusion layer splits it at those boundaries so every
note has one lyric owner; the source candidate and split boundaries are recorded
in provenance and are not counted as interpolation. Direct pitch/phone overlap
must be at least 95%; any nearest interpolation is limited to 5% and recorded in
the provenance sidecar. A user must still import and play the result in
VOCALOID4 before it is product-accepted.

The strict product lane requires an externally supplied, read-only vocal stem,
an audio-hash-bound `lyrics_timeline_v1` file, explicit
`forced_phone_alignment_v1` evidence, and a detached
`forced_phone_acceptance_v1` record. The acceptance record must prove either a
non-NC, immutable, hash-bound model trained or fine-tuned on Cantonese singing,
or an identified human's approved phone-boundary review. Human review must
approve a 10-20 second clip before a full-song record can cite that predecessor.
Automatic MFA output, a trusted manifest, structural validation, or pending
listening review does not satisfy this gate. The lane never distributes lyric
duration uniformly to invent phone timing. ONNX/eSpeak CTC may be supplied
separately as auxiliary comparison evidence:

For the qualified-model route, the acceptance record must point to a detached
`forced_phone_model_manifest_v1` with real byte hashes for the model weights,
dictionary, phone map, and any required tokenizer. Each resource needs an
immutable revision, an explicit non-NC/commercial-use license whose source file
is hash-bound, and the manifest must bind a primary Cantonese-singing training
record to the same model. See
[forced_phone_model_manifest.md](docs/forced_phone_model_manifest.md). A model
that only supports Cantonese speech or merely ships a Cantonese dictionary is
rejected.

```powershell
.\.venv\Scripts\python.exe tools\build_miku_v4c_audio_draft_vsqx.py `
  --audio input.wav --vocal-stem vocals.wav `
  --lyrics-timeline lyrics_timeline.json `
  --forced-phone-alignment forced_phones.json `
  --forced-phone-acceptance forced_phone_acceptance.json `
  --ctc-phone-segments ctc_phones.json `
  --pitch-analysis pitch_analysis.json `
  --template "Human-made_Sections\template.vsqx" `
  --output-root .state\runs\strict-product --strict-product
```

For the human route, first convert the complete raw MFA result into an explicit
machine-only review draft. The default preserves the raw phone intervals. Use
`--timeline-constrained` for a reviewable machine suggestion whose phone order
and raw boundaries remain in provenance while suggested boundaries are mapped
inside the lyric timeline. Both modes record raw timing drift, set
`product_accepted=false`, and are rejected by the normal forced-phone parser
until human review produces a separate alignment and acceptance record:

```powershell
.\.venv\Scripts\python.exe tools\build_mfa_phone_review_draft.py `
  --alignment raw_mfa_alignment.json --vocal-stem full_vocals.wav `
  --lyrics-timeline full_lyrics_timeline.json --model final.mdl `
  --model-revision repository@immutable-revision/model-version `
  --dictionary alignment_dictionary.dict --timeline-constrained `
  --output machine_phone_review_draft.json
```

For singing review, the optional rebalancer replaces pathological machine
within-syllable splits with explicit onset/nucleus/coda duration priors from a
config file. It preserves each lyric item's outer timeline boundaries and the
previous draft SHA-256. This is a review suggestion only: provenance records
`boundary_transform_acoustic_truth=false`, and the output remains
`product_accepted=false` and parser-rejected until human acceptance:

```powershell
.\.venv\Scripts\python.exe tools\rebalance_singing_phone_review_draft.py `
  --alignment machine_phone_review_draft.json `
  --lyrics-timeline full_lyrics_timeline.json `
  --output machine_singing_review_draft.json
```

The initial 10-20 second review may select complete phone rows from a full-song
machine draft while remaining bound to the complete vocal-stem SHA-256. A
window that cuts through a phone is rejected. The project also provides
`rebase_phone_review_clip.py` to prove an exact PCM window when a physically
cropped alignment is the source. Start the local reviewer with the complete
stem. The page groups contiguous phones by the unique lyric item, displays a
repeated Han character once per item, and loops the whole syllable for boundary
review. A group checkbox is an explicit confirmation of every displayed phone
boundary in that syllable; editing any symbol, boundary, or lyric item clears
the entire group. Individual phone playback, insertion, deletion, and review
remain available. Navigation and playback never check anything. A local edit
draft is bound to the audio, alignment, timeline, and review scope. It restores
edited values and row order only; every restored checkbox is cleared and must
be reviewed again:

```powershell
.\.venv\Scripts\python.exe tools\review_forced_phone_alignment.py `
  --audio full_vocals.wav --alignment machine_singing_review_draft.json `
  --lyrics-timeline full_lyrics_timeline.json `
  --lyrics-timeline-audio original_mix.wav --scope short_clip `
  --review-start-sec 66.413 --review-end-sec 83.477 `
  --output-dir human-review-short --port 8766 `
  --next-full-alignment machine_singing_review_draft.json `
  --next-full-output-dir human-review-full --next-full-port 8767
```

Only after that save succeeds may the full-song reviewer start. It validates
the short acceptance and its reviewed phone JSON, requires the same full-stem
hash, records the predecessor in the final acceptance, and exposes an
`Open full-song review` link. The equivalent explicit fallback command is:

```powershell
.\.venv\Scripts\python.exe tools\review_forced_phone_alignment.py `
  --audio full_vocals.wav --alignment machine_phone_review_draft.json `
  --lyrics-timeline full_lyrics_timeline.json `
  --lyrics-timeline-audio original_mix.wav --scope full_song `
  --short-clip-acceptance human-review-short\forced_phone_acceptance_v1.json `
  --output-dir human-review-full --port 8767
```

PyCantonese `5.0.0` (MIT) is the replaceable default Cantonese G2P adapter in
this lane. It is version-locked and does not download models. Timeline Jyutping
or an explicit reviewed `--g2p-lexicon` may override it. Any OOV lyric item,
missing timing, hash mismatch, missing forced phone group, or insufficient
pitch overlap prevents VSQX generation.

## Main directories

- `src/any2xsampa`: runtime packages and adapters.
- `tools`: product, data preparation, training, model packaging, and VSQX
  command-line tools.
- `tests`: current product and training tests.
- `apps/Any2Xsampa.Desktop`: WinUI application.
- `proto`: stable gRPC contract.
- `docs`: current Vocaloid/VSQX implementation notes.

The existing accepted example validates VSQ4 structure, note timing, and Miku V4
phoneme serialization. Its pitch is fixed at MIDI 60 and its lyric is the
placeholder `la`; it remains a historical structural baseline, not the new
pitch/lyrics product candidate.
