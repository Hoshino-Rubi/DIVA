# DIVA v1.1.0 · Windows x64 · Cantonese to Miku V4C

`any2xsampa.cmd cantonese-vsqx song.wav --output song.vsqx` uses the separated vocal, GAME notes, local Whisper plus the acoustic rank-eight final head, a 0.70 checked-coda veto and supervised V13 scoop merging. No lyrics, MIDI or human reference project are inputs. Use `--no-scoop-merge` to keep V9 note boundaries without disabling the coda veto. Experimental sweep/training entry points and the whole-cluster instrumental filter are not part of this package.

**Model setup / 模型准备** (relative to the installation): import the unchanged GAME offline bundle from v1.0.2 to `models/game`. Extract the optional Cantonese4 model archive to `models/cantonese4`; use the desktop Cantonese page's explicit **Prepare models** once (or supply its pinned separator source locally). The archive does not redistribute the separator author's source. Provide the local eSpeak int8 CTC bundle as `models/onnx-espeak/model/onnx/model_int8.onnx` and `models/onnx-espeak/tokenizer/vocab.json`; these are not the GAME or Cantonese4 weights. Use the ONNX weights from onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX (SHA256 74174710e34035bbb7f611601d016c32fc575de7a6f53b1078107dc10a84e7ae) and the original facebook/wav2vec2-lv-60-espeak-cv-ft vocabulary (SHA256 d732ab2456c0c017930001dc9af0b41b3b93d25b2eb9740bf9d925508d7d87d). The two small singing adapters are included in the Windows program. Inference never downloads missing models. Reuse existing local bundles with `--game-snapshot`, `--separator-bundle` and `--model`.

**Device**: `--device auto|cpu|cuda` controls ONNX sessions, not PyTorch vocal separation. The real pipeline still requires a compatible NVIDIA GPU. Auto keeps GAME on CPU to preserve slicing and prefers CUDA for eSpeak, falling back to CPU if unavailable. Explicit CUDA requires a working CUDA EP. Individual operators may still be assigned to CPU by ONNX Runtime. Model weights and sampling parameters were not modified.

**Evidence / 已知局限**: on the six-song historical development benchmark V9 → V13 reduced effective over-splits 198 → 168; V13 pitch errors were 804/1,968 paired notes (40.85%), exact syllables 1,172/2,375, checked codas 183/332. On the two held-out songs, extra notes fell 69 → 62 and checked codas rose 47 → 48, but pitch errors rose 53 → 55 and exact syllables fell 335 → 334. All 3,419/3,419 notes across eight historical V13 projects passed the whole-syllable XML whitelist. Valid XML is not proof of accurate singing.

On one complete development song (自由花), the same seed and frozen models gave 497 notes on CPU vs 498 on CUDA; just 445 onset ticks were shared. ONNX CPU vs CUDA wall time was **373.83 vs 184.52 seconds** including separation and export; GAME including session setup was **173.39 vs 12.71 seconds**. CPU reproduced the prior V13 note times, pitch and syllables exactly. These are single runs on one machine, not general speed guarantees.
