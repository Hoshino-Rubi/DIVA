# DIVA v1.0.4 · Windows x64

[简体中文](v1.0.4_CN.md)

## Cantonese enhancement

The independent **Cantonese (粤语增强)** page runs candidate 4 on the selected WAV, using the existing whole-file or clip selection. Select the extracted optional model folder, press **Prepare models**, then **Start**, and use **Open results** when finished. Controls and status stay simple; the validation details are recorded here.

The path is MelBand vocal separation → Whisper small → completion selection → Jyutping → rule-derived IPA → X-SAMPA export. Separation produces FLOAT vocals with gain 1 and no compensating shift. A complete small decode with EOS takes priority. If small fails or is incomplete, only a complete base decode of the entire same window is accepted; otherwise the window remains explicitly unknown. Outputs retain their source-window positions, raw tokens, unknowns and repetitions, and include TXT, JSON and `vocal.wav`.

Window/source-frame coordinates are not phone boundaries. This feature does not invent `PhoneSegment` times, replace the existing phone recognizer, overwrite its results, or feed automatic VSQX generation. IPA is a rule-based projection of Jyutping, not independently measured acoustic IPA; X-SAMPA remains an export representation. Missing tone or unresolved repetition evidence stays unknown.

## Optional models and runtime

The optional model archive is `DIVA-Cantonese4-Models-v1.0.4.zip`. Extract it and choose the extracted model folder on the Cantonese page. The default location is `models/cantonese4`. The public ZIP excludes the separator author's code.

Press **Prepare models** explicitly before starting. On first preparation, missing separator source/config files are fetched externally as four small files from the fixed upstream commit, checked against their pinned SHA256 values, with a 30-second network timeout and support for the existing proxy setting. The four files are `config_vocals_mel_band_roformer.yaml`, `__init__.py`, `attend.py` and `mel_band_roformer.py`. If matching files have already been supplied, preparation uses no network. Startup and background tasks do not automatically download source.

Separation uses the GPU; recognition uses four CPU threads. Missing GPU support or a separation failure is reported, with no silent CPU separation fallback. Inference after preparation is offline and does not start downloads.

The main program payload includes audio/separation dependencies from 17 pinned wheels totaling 170,899,517 bytes, including `librosa`, `soxr`, `einops`, `rotary_embedding_torch` and `beartype`, alongside the existing phonetic runtime's Torch and Transformers. Dependency imports and 44.1 kHz → 16 kHz resampling passed engineering checks. Model-specific execution stays behind a replaceable adapter. See `RELEASE_ACCEPTANCE` for the dependency inventory and verification details.

## Recorded accuracy evidence

The original `RESULTS_CN` report and `VOCAL_AB_SCORE.json` compare candidate 3 on mixed audio with candidate 4 on separated vocals, keeping the same small/base completion policy. The fixed Train6/7 pool contains 843 author-provided toneless Jyutping syllables in 32 source-clock windows per arm. All outputs, repetitions and unknowns remain in the denominator.

E = substitutions + deletions + insertions; TP = N − substitutions − deletions; FP = substitutions + insertions; FN = substitutions + deletions. Each arrow is mixed → vocal input.

| Fixed input | N | E | TP | FP | FN |
| --- | ---: | ---: | ---: | ---: | ---: |
| Train6 | 405 | 105 → 60 | 306 → 351 | 69 → 53 | 99 → 54 |
| Train7 | 438 | 200 → 74 | 247 → 371 | 93 → 51 | 191 → 67 |
| Fixed pool | 843 | 305 → 134 | 553 → 722 | 162 → 104 | 290 → 121 |

Net changes are E −171, TP +169, FP −58 and FN −169. Edit errors fell 56.0656% relative to the mixed-input baseline; this is not a 56% increase in overall accuracy. Neither song's aggregate E regressed; individual windows or phones are not claimed to improve uniformly.

Both arms completed 32/32 windows, with zero final failures, missing songs or unknown-token windows. Mixed-input small completed 31/32 windows, with one whole-window base fallback; vocal-input small completed 32/32. Four recognition groups made 128 calls with zero call exceptions. Separation had four launches: two import failures before any forward, one interruption after the first song, and one recovery for the second song. The completed first song was reused. Those failed launches and the interruption are retained, not erased by the zero-final-failure count.

This is a fixed research comparison, not an independent blind test. Historical reference-exposure bias remains, and pretraining overlap is unknown. Author lyrics may omit speech or fillers, so FP is an edit-alignment count, not exhaustive acoustic false positives. Reference-clock alignment and separator latency were not independently established; equal frame counts and no applied shift do not prove zero latency. Tones, phone boundaries, short/repeated note events, note accuracy and VOCALOID quality are unproven. The result does not establish broad Cantonese generalization or overall production accuracy.

The v1.0.3 English/Chinese UI and layout improvements, export pitch modes and native-compatible VSQ4 empty-sequence fix are retained; see the [v1.0.3 notes](v1.0.3.md) for their original verification scope.
